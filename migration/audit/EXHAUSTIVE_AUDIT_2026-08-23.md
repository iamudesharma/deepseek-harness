## 1. Summary of All 112 Rows — Five-Layer Verdict

Each row evaluated independently on five layers vs React source (not tracker status, not old notes, not file-name presence):

- **A. CONTRACT** — types/interfaces/models/event/command/state shape, options, validation
- **B. RUNTIME / SERVICES / STATE** — controllers, stores/providers, transitions, lifecycle, persistence, streaming, reconnect, error handling, side effects
- **C. INTEGRATION / COMPOSITION** — PluginHost, service DI, `inject` dependencies, slot registrations, slot kinds/scopes, extension points, routes, navigation, capability deps, cross-plugin interactions
- **D. UI / BEHAVIOR** — components, screens, interactions, keyboard/mouse, overlays, loading/error/empty states, responsive, a11y semantics
- **E. VERIFICATION / EVIDENCE** — focused/integration tests, semantic replay, visual/golden, Web/macOS evidence, artifact paths, tracker metadata

Final classification per spec (evidence-backed):

| Code | Meaning |
|------|---------|
| **COMPLETE** | React behavior fully implemented, integration complete, all parity/evidence requirements satisfied |
| **IMPLEMENTED_BUT_EVIDENCE_MISSING** | Implementation appears complete, required current evidence (test, golden, parity report, platform proof) is missing |
| **PARTIAL** | Some React contract/layer is missing (contract, runtime, integration, or UI gap) |
| **NOT_IMPLEMENTED** | Required functionality is absent (file missing, stub, or empty) |
| **NOT_APPLICABLE** | React contract explicitly does not apply to Flutter (backend seam, host-only) |
| **ARCHITECTURE_MISMATCH** | Flutter has behavior but via a path that violates the React/plugin/slot/service contract (monolith vs registry, standalone map vs slot, synthetic fallback, etc.) |
| **NEEDS_REVIEW** | Insufficient evidence to determine safely (duplicate tracker, stale path with ambiguous fallback) |
